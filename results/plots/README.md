## 3. Методика для отчёта

Benchmark для каждого случая выполняет два прогрева и пять измерений, затем сохраняет медиану в миллисекундах.
Генерация графа находится вне измеряемого вызова алгоритма. Отдельные результаты пяти запусков не сохранены, поэтому разброс и доверительные интервалы по этому CSV восстановить нельзя.
Эталонные проверки MST, SCC и DAG выполняются до записи файла.

Точность интерпретации счётчиков:

- Kruskal: `edge_scans = m`; Prim: `edge_scans = 2m` (списки смежности неориентированного графа).
- Kosaraju: `edge_scans = 2m`, два обхода; создание обратного графа не входит в этот счётчик.
- Kahn и DagShortestPath: `edge_scans = m` в этих данных. Начальный подсчёт входящих степеней не включён. DagShortestPath также вызывает Kahn: его время включено, а просмотры рёбер Kahn не включены в возвращаемый счётчик DagShortestPath.
- Совпадающие линии на третьем графике объединены после проверки всех строк CSV.
- `dsu_ops` — число вызовов find плюс число успешных union. Для этих связных графов равно `2m + n - 1`; это не число всех внутренних операций DSU.
- `max_depth` в текущем коде — максимум размера явного стека в двух проходах Kosaraju. Это не глубина рекурсивных вызовов и не измерение памяти в байтах.
- Нули в неприменимых метриках не интерпретируются как отсутствие работы алгоритма.

## 4. Что можно написать в анализе

При n = 100000:

| Серия | Kruskal, ms | Prim, ms | Prim / Kruskal |
| --- | ---: | ---: | ---: |
| sparse | 53.9701 | 164.1093 | 3.04 |
| dense | 310.8882 | 1252.3515 | 4.03 |

В данном запуске Kruskal быстрее Prim на наибольшем размере в обеих сериях. Вывод относится к текущим реализациям и графам, а не ко всем возможным входам.
Рост числа сравнений и работа с очередью помогают обсуждать различие реализаций, но сами по себе не доказывают причину всей разницы времени.
На небольших размерах время не всегда монотонно. По сохранённым медианам нельзя отделить влияние JIT, GC и фоновой нагрузки.

Сравните эксперимент с теоретическими оценками: Kruskal — сортировка O(m log m) плюс DSU; текущий Prim с очередью рёбер — O(m log m); Kosaraju, Kahn и DAG shortest paths — O(n + m).
При m = 4n или 20n линейные по n + m алгоритмы имеют линейную асимптотику по n. Пять экспериментальных точек иллюстрируют поведение реализации, но не доказывают асимптотическую оценку.
